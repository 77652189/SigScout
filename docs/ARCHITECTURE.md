# SigScout 架构

## 边界与依赖方向

```text
CLI / Streamlit UI
        ↓
     services
   ↙     ↓     ↘
core   adapters  tracked data
        ↓
  local runs / user-supplied files
```

- UI 负责展示、交互状态和调用服务，不解析业务输入、不实现筛选或评分规则。
- CLI 与 UI 都通过服务层进入业务流程；服务层可使用 core 的模型与工具、adapter 的外部接口以及受跟踪的数据映射。
- adapter 只封装外部数据或工具边界；外部工具不可用时，服务层必须能给出可理解的降级结果，而非让规则筛选整体失败。
- `core` 不依赖 UI、服务层或 adapter。项目路径由 `ProjectPaths` 从仓库标记推导，运行产物只能落在本地运行目录。

## 关键不变量

- 候选、重复和证据不可因聚类或代表序列选择而丢失。
- 规则和来源路由映射必须可追溯；可维护的规则数据不能分散硬编码到 UI。
- 共享候选库描述宿主来源的信号肽证据，不按目标蛋白复制建库；目标专属候选、实验反馈、融合构建、定位缓存和导出作为隔离的目标覆盖层。
- 实验反馈只按精确氨基酸序列关联。只有完整融合构建精确一致才是构建级证据；仅 A 段一致只能显示相关实验，不得改变完整构建的定位排序。
- 外部定位结果、加工风险与实验反馈保持独立证据通道；展示和导出时可合并字段，但不得写回原始定位缓存或合成为不可解释的总分。
- 实验引导探索只在相同实验单元类型内比较，以批内归一化结果选择面板；其输出是候选压缩启发式，不是产量模型。
- 候选刷新与来源蛋白定位辅助评估解耦。已完成的来源注释按稳定 accession 在刷新时保留，重新评估时再用 UniProt 与 GO 细胞组分证据更新。
- `sigscout.services` 包级入口刻意不重导出符号；调用方从具体子模块导入，以避免隐式公共 API。
- Streamlit 页面模块放在 `ui/views`，不得使用 `ui/pages`，以免触发框架的自动页面发现。
