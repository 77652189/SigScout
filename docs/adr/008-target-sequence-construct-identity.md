# ADR-008：以目标与完整序列摘要定义融合构建身份

## 背景

旧构建 ID 只包含候选名称和构建类型。不同目标使用同一候选时会发生 ID 冲突，修改固定片段后也可能继续命中旧定位结果；同时，构建上下文只存在于会话内，页面重启后无法可靠验证外部结果属于哪一版构建。

## 决策

融合构建使用 `target__candidate__type__sha1(sequence)[:12]` 作为 ID，并同时保存 schema 版本和完整序列 SHA-1。每个目标保存独立的最新构建清单；定位导入必须以当前目标清单为依据，校验目标、schema、构建 ID 和序列摘要。旧版定位缓存不迁移，必须重新生成 FASTA 并重新计算。

## 后果

不同目标、不同 A/C 序列以及 ABC 中不同 B 序列不会再共享构建身份。页面重启后可从目标清单恢复匹配上下文；代价是本次升级前的外部定位结果全部失效，运行目录仍保留历史兼容名称但不再承载目标语义。
